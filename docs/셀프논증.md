## 쟁점 1: 답·해설·원문을 항상 표시할 것인가 (E-2, E-3)

- 내 주장(실제 답변): “모두 항상 표시하고 접지 않는다.”
- AI 반론: 작은 화면에서 세 영역을 동시에 읽으면 탐색량과 스크롤이 늘어난다. 핵심 답을 찾기 어려울 수 있다(P08).
- 스스로 찾은 반론(실제 답변): “너무 번잡하여 중요한 내용을 빠르게 찾기 어렵다.”
- 재반론·수정안(AI 제안, 학생 확인): 노출 자체는 유지하되 정답을 먼저 두고, 해설과 원문에 서로 다른 제목·배경·여백을 둔다. 기억에 의존하거나 펼침 버튼을 찾지 않고 비교할 수 있다(P06). 세로 스크롤을 허용한다.
- 결론: **수정**. 상시 표시는 유지하고, 접기 UI는 폐기하며, 정보 위계를 정답 우선으로 바꾼다.
- 근거: P06·P08, R06(2026-10-12, ★4)의 복습 보기 불일치. R06은 원문 상시 표시의 효과를 직접 검증한 리뷰는 아니다.
- 전·후: [before-original.png](screenshots/before-original.png)(제공 자료의 초기 비교안) / [explanation-phone-options.jpg](screenshots/explanation-phone-options.jpg)(현재 UI 위젯 테스트). 과거 배포 버전이나 사용자 실험이 아니다.
- 증거: prompt-log U1·U2·U3·A1, 원칙 카드 P06·P08, `lib/screens/explanation.dart`의 E-3.

## 쟁점 2: 해설과 근거를 접기 UI로 숨길 것인가 (E-3, E-4)

- 내 주장(실제 답변): “접지 않는다.”
- AI 반론: 접기/아코디언을 쓰면 작은 화면의 스크롤 길이를 줄일 수 있다. 모든 내용을 한 번에 보여 주는 것보다 탐색이 쉬울 수 있다(P08).
- 스스로 찾은 반론(실제 답변): “너무 번잡하여 중요한 내용을 빠르게 찾기 어렵다.” 즉 상시 표시 자체가 탐색 부담을 만들 수 있다는 점을 인정했다.
- 재반론·수정안(AI 제안, 학생 확인): 접기 버튼을 추가하는 대신 정답을 먼저 두고, 해설과 근거를 제목·색·여백으로 구분한다. 접기 없이도 읽기 순서를 만든다(P06).
- 결론: **수정**. 접기 UI는 폐기하고, 정보 위계와 스크롤 수용으로 대체한다.
- 근거: P06·P08, R06(2026-10-12, ★4). 접기 UI의 효과는 사용자 실험으로 검증하지 않았다.
- 전·후: [before-folded.png](screenshots/before-folded.png)(접기 비교안) / [explanation-phone-options.jpg](screenshots/explanation-phone-options.jpg)(현재 UI 위젯 테스트).
- 증거: prompt-log U1·U2·U3·A1, 원칙 카드 P06·P08, `lib/screens/explanation.dart`의 E-3.

## 쟁점 3: 해설 데이터를 별도로 만들 것인가 (Q-2, E-2)

- 설계 초안(AI): 화면마다 별도 정답 목록을 만든다.
- AI 반론: 목록 순서가 바뀌면 같은 index라도 다른 문항의 답이 보일 수 있다(P04).
- 검토 반론(AI 작성): 동일 객체 전달만으로 원본 데이터 자체의 오류까지 없애지는 못한다. 원래 보기와 내 선택을 화면에 표시하지 않으면 R06의 불일치를 사용자가 확인할 수 없다.
- 재반론·수정: questions와 index를 그대로 전달하고, E 화면에서 같은 q의 `options`, `answer`, `explanation`, `source`를 읽는다. 원래 보기와 내 선택을 함께 표시하고, 실제 데이터의 정답·근거 일치를 테스트한다. 교육 내용 정확성은 별도 검토한다.
- 결론: **수정**. 별도 해설 목록은 폐기.
- 근거: P04, R06. 현재 코드는 같은 q에서 answer/explanation/source를 읽고, `selected`를 Q에서 E로 전달한다.
- 전·후: [before-separate-answer.png](screenshots/before-separate-answer.png)(별도 정답 목록 비교안) / [explanation-wide.jpg](screenshots/explanation-wide.jpg)(현재 1280px 위젯 테스트).
- 증거: prompt-log A2, 원칙 카드 P04, `test/widget_test.dart`의 E-2 원래 보기·내 선택 검증.
- 작성 구분: 이 쟁점은 AI 검토안이며 학생의 독립 반론을 주장하지 않는다.

## 쟁점 4: 오류를 잠깐만 알릴 것인가 (C-2)

- 설계 초안(AI): 실패 메시지를 잠시 띄운 뒤 없앤다.
- AI 반론: 메시지가 사라지면 실패 이유와 복구 행동이 없어져 사용자가 기다려야 하는지 판단하기 어렵다(P09).
- 검토 반론(AI 작성): 항상 남는 오류도 화면을 차지한다. 반복 재시도로 실패가 계속될 수 있다.
- 재반론·수정: 안내, 다시 시도, 입력으로 돌아가기만 지속 표시한다. 개발 서버 주소는 제품 문구에서 제외한다.
- 결론: **수정**. 일시적 알림만 사용하는 안은 폐기.
- 근거: P09·P01. R23의 파싱 실패와 네트워크 오류는 다른 원인이므로 복구 요구의 간접 근거로만 사용한다.
- 전·후: [before-toast-error.png](screenshots/before-toast-error.png)(일시 알림 비교안) / [error-browser.jpg](screenshots/error-browser.jpg)(현재 지속 오류 화면).
- 증거: prompt-log A3, 원칙 카드 P09, `lib/widgets.dart`의 C-2, 재시도 테스트.
- 작성 구분: 이 쟁점은 AI 검토안이며 학생의 독립 반론을 주장하지 않는다.

## 쟁점 5: 선택 전에 해설 확인 버튼을 막을 것인가 (Q-3)

- 내 주장(설계 결정): 선택 전에는 `Q-3 정답과 해설 확인` 버튼을 비활성화한다.
- AI 반론: 답을 고르지 않고 해설을 먼저 보고 싶은 사용자에게는 통제가 제한될 수 있다(P03).
- 스스로 찾은 반론(설계 검토): 선택을 강제하면 빠르게 복습하려는 사용자에게 마찰이 생긴다.
- 재반론·수정: 선택은 화면 안에서만 표시하고, 선택 전에는 버튼을 비활성화하되 선택하면 즉시 활성화한다. 채점하지 않는다.
- 결론: **유지**. 선택 전 비활성화는 유지하고, 선택 후 즉시 다음 화면으로 이동한다.
- 근거: P05, P03. 선택 누락을 줄이는 오류 예방이 우선이다.
- 전·후: [before-confirm-enabled.png](screenshots/before-confirm-enabled.png)(선택 전에도 활성화된 비교안) / [quiz-phone.jpg](screenshots/quiz-phone.jpg)(선택 후 활성화된 현재 화면).
- 증거: prompt-log A4, 원칙 카드 P05, `lib/screens/quiz.dart`, 320px E 화면 테스트.
- 작성 구분: 이 쟁점은 학생 요청으로 현재 구현 결정을 정리한 설계 논증이며, 실제 발화 인용이 아니다.

## 쟁점 6: E 화면에 원래 보기와 내 선택을 표시할 것인가 (Q-2, E-2)

- 내 주장(설계 결정): 해설 화면에 원래 보기 전체와 내 선택을 함께 표시한다.
- AI 반론: 정답·해설·보기·근거가 한 화면에 늘어나 작은 화면의 스크롤이 길어진다(P08).
- 스스로 찾은 반론(설계 검토): R06의 핵심은 원래 보기와 복습 보기가 달라지는 경험이다. 보기를 숨기면 그 문제를 해결했다고 보기 어렵다.
- 재반론·수정: 정답과 해설 아래에 원래 보기를 두고, 정답과 내 선택을 badge로 구분한다. 접지 않고 스크롤을 허용한다.
- 결론: **수정**. 정답만 보여 주는 안에서 원래 보기·내 선택을 함께 보여 주는 안으로 바꾼다.
- 근거: P04, P06, P08, R06(2026-10-12, ★4).
- 전·후: [before-original.png](screenshots/before-original.png)(정답만 표시한 비교안) / [explanation-phone-options.jpg](screenshots/explanation-phone-options.jpg)(원래 보기·내 선택을 표시한 현재 화면).
- 증거: prompt-log A5, 원칙 카드 P04, `lib/screens/explanation.dart`, E-2 원래 보기·내 선택 테스트.
- 작성 구분: 이 쟁점은 학생 요청으로 현재 구현 결정을 정리한 설계 논증이며, 실제 발화 인용이 아니다.

## 쟁점 7: 결과 화면에 실제 점수를 표시할 것인가 (R-1)

- 내 주장(설계 결정): 결과 화면은 실제 채점 대신 고정 예시 `2 / 3`을 표시한다.
- AI 반론: 사용자가 실제 점수로 오해할 수 있으므로 P01 상태 가시성을 위반할 수 있다.
- 스스로 찾은 반론(설계 검토): 실제 점수를 넣으면 UI-only 범위를 넘고, 선택과 무관한 결과가 생긴다.
- 재반론·수정: 결과 상단과 버튼에 `예시 결과`, `고정 예시`를 명시하고, 실제 채점·저장은 하지 않는다.
- 결론: **유지 + 표현 수정**. 고정 예시는 유지하고, 예시임을 더 분명히 표시한다.
- 근거: P01, UI-only 범위.
- 전·후: [before-real-score.png](screenshots/before-real-score.png)(실제 점수처럼 표시한 비교안) / [result-phone.jpg](screenshots/result-phone.jpg)(예시 결과로 표시한 현재 화면).
- 증거: prompt-log A6, 원칙 카드 P01, `lib/screens/result.dart`, 고정 결과 테스트.
- 작성 구분: 이 쟁점은 학생 요청으로 현재 구현 결정을 정리한 설계 논증이며, 실제 발화 인용이 아니다.

## 검토 한계

- 쟁점 1·2는 학생이 실제로 선택하고 반론한 범위다.
- 쟁점 3·4는 AI가 설계 초안과 반론을 만들었으며, 학생의 독립 반론으로 가장하지 않았다.
- 쟁점 5·6·7은 학생 요청으로 현재 구현 결정을 정리한 설계 논증이다. 새로운 학생 발화를 만들지 않기 위해 `실제 발화 인용`과 구분했다.
- before 이미지는 과거 배포본이나 사용자 실험이 아니라 설계 비교를 위해 만든 정적 비교안이다.
- 상시 표시, 접기 폐기, 원래 보기·내 선택, 선택 전 차단, 고정 결과의 효과는 아직 사용자 테스트로 검증하지 않았다.
