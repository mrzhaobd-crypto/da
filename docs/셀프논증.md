# NoteQuiz 셀프 논증 기록
작성: 2026-10-29. 학생: zhaoboda / 2025106293. AI: Codex.
아래는 이번 작업의 실제 사용자 응답과 AI 검토를 구분한 기록이다. 학생이 말하지 않은 이유를 학생 발언으로 만들지 않았다.

## 쟁점 1: 답·해설·원문을 항상 표시할 것인가 (E-2, E-3)
- 내 주장(실제 답변): “全部常显，不折叠” / 모두 항상 표시하고 접지 않는다.
- AI 반론: 작은 화면에서 세 영역을 동시에 읽으면 탐색량과 스크롤이 늘어난다. 핵심 답을 찾기 어려울 수 있다(P08).
- 스스로 찾은 반론(실제 답변): “太繁琐无法快速检索重要内容” / 너무 번잡하여 중요한 내용을 빠르게 찾기 어렵다.
- 재반론·수정안(AI 제안): 노출 자체는 유지하되 정답을 먼저 두고, 해설과 원문에 서로 다른 제목·배경·여백을 둔다. 기억에 의존하거나 펼침 버튼을 찾지 않고 비교할 수 있다(P06). 세로 스크롤을 허용한다.
- 결론: **유지 + 표현 수정**. 접기 기능은 폐기. ‘모두 표시’는 사용자 확인됨. 위 재반론은 AI가 제안한 후 학생이 “符合，作为我的最终判断”이라고 확인했다. 즉 직접 대조를 위해 상시 표시를 유지하되 정답 우선·영역 구분과 필요한 스크롤을 수용하는 최종 판단이다.
- 근거: P06·P08, R06(2026-10-12, ★4) 복습 보기 불일치. R06은 원문 상시 표시가 효과적임을 직접 검증한 리뷰는 아니다.
- 전·후: `screenshots/before-original.png`(제공 자료의 초기 비교안) / `screenshots/explanation-phone.jpg`(현재 브라우저 실행). 과거 배포 버전이나 사용자 실험이 아니다.
- 증거: prompt-log U1/U2/U3/A1, 원칙 카드 P06, `lib/screens/explanation.dart`의 E-3.

## 쟁점 2: 해설 데이터를 별도로 만들 것인가 (Q-2, E-2)
- 설계 초안(AI): 화면마다 별도 정답 목록을 만든다.
- AI 반론: 목록 순서가 바뀌면 같은 index라도 다른 문항의 답이 보일 수 있다(P04).
- 검토 반론(AI 작성): 동일 객체 전달만으로 원본 데이터 자체의 오류까지 없애지는 못한다.
- 재반론·수정: questions와 index를 그대로 전달하고, 실제 데이터의 정답·근거 일치를 테스트한다. 교육 내용 정확성은 별도 검토한다.
- 결론: **수정**. 별도 해설 목록은 폐기.
- 근거: P04, R06. 현재 코드는 같은 q에서 answer/explanation/source를 읽는다.
- 전·후: 초기 비교안 / `screenshots/quiz-wide.jpg`와 `explanation-wide.jpg`.
- 증거: prompt-log A2; 원칙 카드 P04; 전체 문항 흐름 테스트.
- 작성 구분: 이 쟁점은 AI 검토안이며 학생의 독립 반론을 주장하지 않는다.

## 쟁점 3: 오류를 잠깐만 알릴 것인가 (C-2)
- 설계 초안(AI): 실패 메시지를 잠시 띄운 뒤 없앤다.
- AI 반론: 메시지가 사라지면 실패 이유와 복구 행동이 없어져 사용자가 기다려야 하는지 판단하기 어렵다(P09).
- 검토 반론(AI 작성): 항상 남는 오류도 화면을 차지한다. 반복 재시도로 실패가 계속될 수 있다.
- 재반론·수정: 안내, 다시 시도, 입력으로 돌아가기만 지속 표시한다. 개발 서버 주소는 제품 문구에서 제외한다.
- 결론: **수정**. 일시적 알림만 사용하는 안은 폐기.
- 근거: P09·P01. R23의 파싱 실패와 네트워크 오류는 다른 원인이므로 복구 요구의 간접 근거로만 사용한다.
- 전·후: 별도 과거 구현은 없으며 초안은 문장으로 비교. 현재 공통 오류 캡처와 재시도 테스트를 증거로 사용한다.
- 증거: prompt-log A3, 원칙 카드 P09, `lib/widgets.dart`.
