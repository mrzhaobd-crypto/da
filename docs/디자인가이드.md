# 디자인 가이드

화면 흐름: I → S → Q → E → 다음 Q 또는 R. 화면 전환은 `Navigator.push`/`pop`/`popUntil`을 사용한다. 공통 C 상태는 별도 제품 화면이 아니라 각 GET 화면의 분기다.

## 기본 규칙

- 색상: 배경 `#F5F7FC`, 본문 `#18243B`, 강조 `#4F609B`, 보조 패널 `#E9EEFC`.
- 글자: 본문 16px 이상, 화면 제목 29px, 패널 본문 18px, 보조 문구 12px.
- 버튼: FilledButton·OutlinedButton·TextButton 모두 최소 높이 52px.
- 여백: 화면 가장자리 24px, 카드 안쪽 22px, 카드 사이 16px.
- 반응형: 창 너비 840px 이상이면 측면 안내, 요약 영역 720px 이상이면 3열. 기기 이름이 아니라 창 너비로 판단한다.
- 글꼴: 시스템 글꼴. 별도 웹폰트를 내려받지 않는다.
- 상태: 기본·선택·비활성·오류·로딩을 색만이 아니라 텍스트와 아이콘으로도 구분한다.

## I 강의 입력 · `lib/screens/input.dart`

목적: 강의 텍스트를 붙여넣고 복습을 시작한다.

내용: 입력 영역, 예시 불러오기, 예시 요약 확인 순서.

의도: 빈 입력은 같은 영역에 안내하고, 입력을 시작하면 오류 문구를 즉시 지운다. 입력은 전송·저장하지 않는다.

| 번호 | Flutter 위젯 | 비즈니스 명칭 | 정보 전달 기준 | 편의성 포인트 | 원칙·이유 |
|---|---|---|---|---|---|
| I-1 | TextField | 강의 내용 | 화면 상단에 6~10줄 입력 영역, label·hint·error를 같은 영역에 표시 | 입력 즉시 오류 문구 해제, 320px에서도 가로 스크롤 없음 | P05 빈 입력 오류를 사전에 안내 |
| I-2 | TextButton | 예시 강의 불러오기 | 입력 영역 바로 아래에 위치, 버튼을 누르면 예시 문장이 채워짐 | 빈 화면에서 첫 행동을 만들고, 최소 52px 터치 영역 확보 | P06 기억에 의존하지 않고 예시로 시작 |
| I-3 | FilledButton | 예시 요약 확인 | 버튼 이름에 ‘예시’를 명시하고, 다음 화면이 고정 예시임을 먼저 알림 | 입력이 비면 같은 영역에 안내하고 화면 이동을 막음 | P01 현재 상태와 예시 여부를 명확히 표시 |

## S 핵심 요약 · `lib/screens/summary.dart`

목적: 퀴즈 전에 핵심 개념을 확인한다.

내용: 세 주제의 제목·요약·근거와 퀴즈 시작.

의도: 영역 너비 720px 이상은 3열, 좁으면 세로 스크롤. 카드마다 같은 정보 순서를 반복한다.

| 번호 | Flutter 위젯 | 비즈니스 명칭 | 정보 전달 기준 | 편의성 포인트 | 원칙·이유 |
|---|---|---|---|---|---|
| S-1 | Container + Text | 선언형 UI | 카드 첫 줄에 주제명, 그 아래 요약, 마지막에 근거 | 긴 요약은 줄바꿈, 카드 전체를 한 번에 읽게 함 | P08 핵심 제목을 먼저 보여 줌 |
| S-2 | Container + Text | 레이아웃과 제약 | S-1과 같은 제목·요약·근거 순서 | 카드 간 16px 간격, 3열에서도 읽기 순서 유지 | P04 화면마다 같은 정보 위계 |
| S-3 | Container + Text | 수평 프로토타입 | S-1과 같은 카드 형식, 근거를 생략하지 않음 | 좁은 화면은 세로, 넓은 화면은 3열 | P04 동일한 정보 구조 |
| S-4 | FilledButton | 복습 퀴즈 시작 | 요약 카드 아래에서 다음 과업을 명시 | 52px 버튼, 키보드·터치 모두 접근 가능 | P07 다음 과업으로 빠르게 이동 |

## Q 복습 퀴즈 · `lib/screens/quiz.dart`

목적: 스스로 답을 떠올린 뒤 해설로 이동한다.

내용: 진행 표시, 선택지, 확인 버튼.

의도: 선택 전에는 확인 버튼을 비활성화하고, 선택 표시만 바꾼다. 채점하지 않는다.

| 번호 | Flutter 위젯 | 비즈니스 명칭 | 정보 전달 기준 | 편의성 포인트 | 원칙·이유 |
|---|---|---|---|---|---|
| Q-1 | Text + LinearProgressIndicator | 문항 진행 안내 | `문항 2 / 3 · OX`와 진행 막대를 함께 표시 | 현재 위치를 텍스트와 그래픽으로 중복 제공 | P01 현재 위치를 인지 |
| Q-2 | OutlinedButton | 보기 선택 | 한 문항의 `options`만 표시, 선택은 배경·점·굵기로 구분 | 선택지를 52px 이상으로 만들고 긴 보기는 줄바꿈 | P04 같은 문항의 보기만 사용 |
| Q-3 | FilledButton | 정답과 해설 확인 | 선택 전에는 비활성, 선택 후에만 다음 화면으로 이동 | 비활성 이유가 보이도록 선택 전 회색 처리 | P05 선택 누락 오류를 예방 |

## E 정답과 해설 · `lib/screens/explanation.dart`

목적: 정답의 이유를 원래 보기, 내 선택, 강의 근거와 비교한다.

내용: 진행, 문항, 정답·해설, 원래 보기·내 선택, 근거, 다음 행동.

의도: 모든 내용을 항상 표시하고 색·제목·여백으로 나눈다. 접기 없음.

| 번호 | Flutter 위젯 | 비즈니스 명칭 | 정보 전달 기준 | 편의성 포인트 | 원칙·이유 |
|---|---|---|---|---|---|
| E-1 | Text | 문항 진행 안내 | `해설 1 / 3`을 화면 첫 줄에 표시 | Q 화면과 같은 번호 체계 | P01 현재 해설 위치를 인지 |
| E-2 | Container + Text | 정답과 해설 | 정답 → 해설 → 원래 보기 → 내 선택 순서, 정답과 내 선택을 badge로 구분 | 접기 없이 스크롤, 원래 보기를 정답과 같은 객체에서 읽음 | P04 같은 문항의 답·보기·선택을 일치 |
| E-3 | Container + Text | 강의 근거 | 정답·해설 아래에 원문을 항상 표시, 색과 제목으로 구분 | 근거를 찾기 위해 앞 화면으로 돌아가지 않음 | P06 기억 부담을 줄이고 재인 지원 |
| E-4 | FilledButton | 다음 문제 / 예시 결과 보기 | 다음 행동을 버튼 하나로 명시, 마지막 문항에서는 결과로 이동 | 52px 버튼, 읽은 뒤 바로 이동 | P07 다음 과업으로 빠르게 이동 |

## R 예시 결과 · `lib/screens/result.dart`

목적: 복습할 개념과 재진입 경로를 보여 준다.

내용: 예시 결과, 다시 볼 개념, 해설 재진입, 새 입력.

의도: 결과가 선택과 무관한 고정 예시임을 밝힌다.

| 번호 | Flutter 위젯 | 비즈니스 명칭 | 정보 전달 기준 | 편의성 포인트 | 원칙·이유 |
|---|---|---|---|---|---|
| R-1 | Text | 예시 결과 안내 | `예시 결과 2 / 3`과 `고정 예시` 문구를 함께 표시 | 실제 채점 결과로 오해하지 않게 함 | P01 실제 상태와 예시를 구분 |
| R-2 | Container + Text | 다시 볼 개념 | 다시 볼 개념을 한 문장으로 제시 | 결과 화면에서 바로 복습 대상 확인 | P06 기억보다 화면의 단서를 사용 |
| R-3 | OutlinedButton | 해설 다시 보기 | 첫 문항 해설로 이동하는 경로를 명시 | 52px 버튼, 결과에서 바로 재진입 | P03 사용자가 복습 경로를 선택 |
| R-4 | FilledButton | 새 강의 입력 | 첫 화면으로 돌아가는 주 행동을 강조 | `popUntil`로 중간 화면을 모두 정리 | P03 사용자가 흐름을 벗어날 수 있게 함 |

## 공통 C 읽기 상태

| 번호 | 위젯 | 비즈니스 명칭 | 정보 전달 기준 | 편의성 포인트 | 원칙·이유 |
|---|---|---|---|---|---|
| C-1 | LoadingView | 읽기 중 | 스피너와 `학습 자료를 불러오는 중…`을 함께 표시 | 요청이 진행 중임을 텍스트로도 알림 | P01 진행 상태를 인지 |
| C-2 | ErrorView | 오류와 다시 시도 | 실패 이유, 다시 시도, 강의 입력으로를 지속 표시 | 오류가 사라지지 않고 복구 행동을 제공 | P09 오류에서 복구 |
| C-3 | EmptyView | 빈 목록 | 성공한 빈 응답임을 설명하고 입력 복귀 제공 | 연결 실패와 빈 결과를 혼동하지 않음 | P01·P03 상태 구분과 복귀 |

## 상태관리 포인트(계획)

| 데이터 | 행동 | 표시 위젯 | 범위 |
|---|---|---|---|
| 입력 텍스트 | 입력·예시 | I-1 | 화면 내부 controller |
| 선택한 보기 | 클릭 | Q-2 | `setState`, 저장·채점 없음 |
| 선택한 보기 전달 | 해설 이동 | E-2 | 생성 인수, 채점 없음 |
| 문항 위치 | 다음 | Q-1 / E-1 | 화면 생성 인수 |
| 요청 상태 | GET·재시도 | C-1~3 | FutureBuilder, 화면 내부 |
| 학습 기록 | 향후 완료 | R | 구현하지 않음 |
| 실제 AI 응답 | 향후 생성 | S/Q/E | 구현하지 않음 |

공유 상태관리·쓰기 API·영구 저장은 없다. 현재 로컬 표시와 향후 상태관리 계획을 구별한다.

## 검증 기준

- 320px·390px에서 가로 오버플로가 없다.
- 840px 이상에서 측면 안내가 보이고, 720px 이상 요약 영역에서 3열이 된다.
- 모든 GET 화면에 로딩·오류·빈 상태가 있다.
- E 화면에서 원래 보기와 내 선택이 같은 문항 객체에서 표시된다.
- FilledButton·OutlinedButton·TextButton의 최소 높이가 52px이다.
